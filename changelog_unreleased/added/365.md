- `/freshness` measures installed-asset freshness on demand (SPEC §4.5, §5.9's measuring stage): it compares the committed pin, the verified installed-pin record and the clone's complete carried files through the pin's own carried aggregate, and renders one content-free line — `current`, `placement-mismatch` (run `node .github/bin/gitjig-bootstrap.mjs`), `session-stale` (run `/reload`) or `cannot-measure` (run the provision command, or `/reload` when only the load-time capture is missing) — never provisioning, writing a pin or aborting. What the provision run converges, refuses or leaves alone is SPEC §4.6's *Installed-pin authority*; the launcher's own stop causes are SPEC §4.2's, their exit statuses SPEC §4.7's. Known false positives: an intended local edit to a carried file reads `placement-mismatch`, a provision running at the same time reads `placement-mismatch` until it advances the record, and a carried data file edited when this process loaded and corrected since reads `session-stale` though no imported code changed. It runs only when asked under a 2-second read budget and caches nothing; an always-on session surface waits for observed precision. (#365)
