- `/freshness` measures installed-asset freshness on demand (SPEC §4.5, §5.9's measuring stage): it compares the committed pin, the verified installed-pin record and the clone's complete carried files through the pin's own carried aggregate, and renders one content-free line — `current`, `placement-mismatch` (run `node .github/bin/gitjig-bootstrap.mjs`), `session-stale` (run `/reload`) or `cannot-measure` — never provisioning, writing a pin or aborting. Known false positives: an intended local edit to a carried file reads placement-mismatch, a concurrent provision reads cannot-measure, and a case- or normalization-insensitive filesystem can read a rename. The launcher converges only when every handed-over file is exactly its committed bytes and, under a present record, every listed carried file is exactly the old or new bytes (under an absent record, absent or new); it refuses edited, foreign, missing-while-both-listed, linked or non-regular carried files, older files under an absent record, a malformed record, a changed source or a class transition, and leaves a carried file neither pin lists alone, so first restore exact bytes, or remove the record and every carried file that is not exactly the new bytes, and remove an unlisted extra; `/freshness help` spells out each step. It runs only when asked under a 2-second read budget and caches nothing; an always-on session surface waits for observed precision. (#365)
