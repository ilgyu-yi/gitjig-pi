- `/freshness` measures installed-asset freshness on demand (SPEC §4.5, §5.9's measuring stage): it compares the committed pin, the verified installed-pin record and the clone's complete carried files through the pin's own carried aggregate, and renders one content-free line — `current`, `placement-mismatch` (run `node .github/bin/gitjig-bootstrap.mjs`), `session-stale` (run `/reload`) or `cannot-measure` — never provisioning, writing a pin or aborting. Known false positives: an intended local edit to a carried file reads placement-mismatch, a provision running at the same time reads placement-mismatch until it advances the record, and a case- or normalization-insensitive filesystem can read a rename. The launcher's provision run converges only when every handed-over file is exactly its committed bytes (and one only the old pin lists is absent) and, under a present record, each carried file both pins list is exactly the old or new bytes, one only the new pin lists is absent or new, and one only the old pin lists is old or absent (under an absent record, every listed carried file is absent or new); it refuses otherwise, on a malformed, unreadable or non-regular record, an unreadable carried file, a changed source or a class transition, and leaves a carried file neither pin lists alone; the launcher can also stop before provision (invalid-input 64, snapshot-identity-mismatch 65, source-unavailable 69, temporary-storage-unavailable 73) or report cleanup-failed (74), each with its step in the help. So first restore exact bytes, or remove the record and every carried file that is not exactly the new bytes, and remove an unlisted extra; `/freshness help` spells out each step. It runs only when asked under a 2-second read budget and caches nothing; an always-on session surface waits for observed precision. (#365)
